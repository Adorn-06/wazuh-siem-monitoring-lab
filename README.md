# 🛡️ Wazuh SIEM Monitoring Lab

A hands-on **Security Operations Center (SOC) lab** built with **Wazuh** to practice SIEM-based security monitoring, endpoint telemetry collection, alert detection, log analysis, file integrity monitoring, and security investigation in a controlled laboratory environment.

The project uses **Windows with Sysmon** for endpoint security-event monitoring and **Kali Linux** for File Integrity Monitoring (FIM) and security testing.

---

## 📌 Project Overview

This project was created to gain practical experience with a SIEM platform and understand how security events generated by endpoints can be collected, analyzed, detected, and investigated.

The lab focuses on:

* SIEM-based security monitoring
* Windows Event Log analysis
* Sysmon telemetry
* Security alert detection
* Brute-force activity analysis
* Discovery activity monitoring
* Defense-evasion testing
* File Integrity Monitoring (FIM)
* Custom Wazuh detection rules
* SOC alert investigation
* MITRE ATT&CK mapping

The project follows a basic SOC workflow:

```text
Endpoint Activity
       ↓
Log / Event Generation
       ↓
Wazuh Collection
       ↓
Event Analysis & Detection
       ↓
Alert Generation
       ↓
SOC Investigation
       ↓
MITRE ATT&CK Mapping
       ↓
Documentation
```

---

# 🎯 Objectives

The main objectives of this lab were to:

* Understand the architecture and workflow of Wazuh.
* Monitor security events generated by Windows endpoints.
* Use Sysmon telemetry for endpoint visibility.
* Analyze authentication and process-related events.
* Test security detections in a controlled environment.
* Investigate brute-force, discovery, and defense-evasion activity.
* Configure and test File Integrity Monitoring.
* Develop and test custom Wazuh detection rules.
* Investigate alerts through the Wazuh dashboard.
* Map observed security activity to the MITRE ATT&CK framework.
* Document the complete detection and investigation process.

# 🔎 Security Monitoring

## Windows Event Monitoring

Windows security telemetry was monitored to identify and investigate activities such as:

* Authentication failures
* Process creation
* Account-related activity
* Command execution
* Security-relevant system activity

The project focused particularly on Windows security events including:

### Event ID 4625

**Failed logon**

Used to investigate authentication failures and identify patterns that may indicate repeated unsuccessful authentication attempts.

### Event ID 4688

**Process creation**

Used to analyze process execution activity and investigate the processes and command-line information available in the collected telemetry.

---

# 🧩 Sysmon Monitoring

**Sysmon** was used to provide additional Windows endpoint telemetry.

The collected telemetry was analyzed to improve visibility into:

* Process creation
* Command execution
* Parent/child process relationships where available
* Security-relevant endpoint activity

Sysmon events were reviewed through the Wazuh monitoring pipeline to support endpoint investigation.

## 2. Discovery Activity

Discovery-related commands were tested to understand how endpoint activity appears in security telemetry.

Examples included controlled testing with commands such as:

```cmd
net user
```

and:

```cmd
tasklist
```

The resulting telemetry was reviewed to determine whether the activity was visible and/or generated a Wazuh alert.

# 🔬 SOC Investigation Workflow

The investigations in this project follow a basic SOC workflow:

```text
Alert / Event
      ↓
Initial Triage
      ↓
Validate Activity
      ↓
Collect Evidence
      ↓
Analyze Event Context
      ↓
Determine Finding
      ↓
MITRE ATT&CK Mapping
      ↓
Document Investigation
```

The purpose is to demonstrate how security alerts can be investigated rather than simply acknowledging that an alert was generated.

# 🧠 MITRE ATT&CK Mapping

Observed activities were mapped to the **MITRE ATT&CK framework** where the available evidence supported a technique mapping.

The mapping process follows:

```text
Observed Activity
       ↓
Security Event
       ↓
Wazuh Detection
       ↓
Investigation
       ↓
Behavior Analysis
       ↓
MITRE ATT&CK Technique
       ↓
ATT&CK Tactic
```



The mapping is based on the behavior actually observed during the controlled lab tests rather than assigning techniques solely based on the command name.
